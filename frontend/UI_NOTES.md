# 侨批 RAG 前端 UI 记录

> 参考文件来源：`D:\自然语言处理期末项目\ui参考\DESIGN.md`、`variables.css`、`tokens.json`、`theme.css`。这些文件来自 Ventriloc 风格参考，只学习结构、空间、卡片系统和组件审美，不照搬其品牌色、文案和橙色视觉识别。

## 一、当前项目视觉方向

- 页面主背景使用浅灰白 / 微米白，整体更接近清爽白色数据工作台，而不是明显发黄的旧纸页面。
- 卡片以白色或接近白色为主，配合轻边框、极轻阴影，形成“纸张 / 档案 / 数据面板”的层级。
- 主色使用深青绿，承担导航选中、主按钮、关键 badge、交互高亮等角色。
- 文字使用深灰黑 / 墨绿，正文保持稳重、专业、可阅读。
- 辅助色使用低饱和蓝灰、浅米色、淡绿色。
- 少量暖金 / 棕色只作为文化感点缀，例如印章、古纸、水墨装饰、少量图表辅助色。
- 不要大面积橙色，不照搬 Ventriloc 的 Signal Orange。
- 不要亮蓝，不要回到普通后台系统默认蓝。
- 不要暗黑风、粒子背景、3D、人物插画、stock photo。
- 首页可以有淡古纸、水墨、侨批书信氛围，但必须是背景层，不能遮挡主标题、正文和按钮。

## 二、从设计系统中学习的结构规则

- 顶部导航适合使用 floating pill nav：白色 / 半透明白底、轻边框、轻阴影、居中悬浮。
- 首页 hero 使用“左文案 + 右产品预览”的结构，而不是普通后台首页。
- 左侧 hero 应包含大标题、简洁说明和两个 pill 按钮，形成清晰入口。
- 右侧 dashboard preview cards 是首页视觉主体，不是普通后台卡片列表。
- preview cards 应错落漂浮，保留空气感；轻微重叠可以，但不能挤成一团。
- 白色卡片应配轻边框、极轻阴影，不使用厚重投影。
- 卡片圆角建议 8–12px，按钮 / badge / tag 使用 20px 或 full pill 圆角。
- 页面布局需要舒适留白，section gap 可以达到 72–96px，卡片间距不要只靠 8px/12px。
- 卡片 padding 建议 24–40px，数据工作台组件可以更密，但首页 hero 必须更舒展。
- dashboard preview card 内部内容应模拟真实产品能力，例如检索、元数据、白话释读、证据追踪，而不是纯装饰。
- 首页视觉应该是“现代 AI 档案工作台”：清爽、专业、可演示，有档案文化温度。
- 功能 strip 应在 hero 下方形成独立区域，不要挤压 hero 主体。

## 三、适配侨批 RAG 的前端设计原则

- 结构学习 Ventriloc：floating nav、hero 双栏、preview cards、白色面板、pill 按钮、舒适留白。
- 配色必须回到侨批 RAG：深青绿主色、墨绿文字、浅灰白画布、低饱和辅助色、少量暖金棕。
- 首页第一屏要回答四件事：系统是什么、能做什么、从哪里开始、NLP/RAG 体现在哪里。
- 左下角档案装饰可以使用本地水墨 / 纸张素材，但要通过 opacity、mix-blend-mode、mask-image 控制为背景氛围。
- 古纸装饰不能使用乱码、假中文、重复无意义文字；更适合用淡墨线条、纸张纹理、印章轮廓和水墨晕染。
- 首页 `/` 不应该显示后台侧边栏和顶部栏；功能页继续保留后台工作台布局。
- 六个功能页更像“工作台内部页面”，首页更像“系统入口页”，两者视觉角色不同。
- 功能页可以保持数据密度，首页必须更舒展、更有叙事性。

## 四、已经踩过的坑

- 只改 CSS 配色没有用，页面会像普通后台换皮肤。
- Codex 容易保守微调，看起来像没改；需要明确给数值，例如 `margin-top`、card `width`、`top`、`left`、`z-index`。
- 左下角古纸装饰不能用乱码或假中文，否则像错误水印。
- 背景素材如果白底明显，需要使用 `mix-blend-mode: multiply`、低透明度、`filter` 和 `mask-image` 融入页面。
- 右侧卡片不能过度重叠，每张至少大部分内容可见。
- dashboard preview cards 不是普通网格，也不能挤成一团；要错落、有空气感、像漂浮产品卡片组合。
- 底部功能 panel 不能太靠上，否则会挤压 hero 区域。
- 首页 `/` 不应该显示原来的后台侧边栏。
- 不要一次同时改六个页面，应该一页一页改。
- 不要为了“文化感”把页面做得太黄、太旧、太纸张化；目标是清爽白色数据工作台 + 轻微档案感。

## 五、后续每次修改前必须遵守

- 先说明将修改哪些文件。
- 不改 `backend/`。
- 不改 API 请求逻辑。
- Mock 只能由 `VITE_DEMO_MODE=true` 显式启用；正式运行不得静默回退。
- 不改 `package.json`，除非明确要求。
- 不改其他页面业务逻辑。
- 改完运行 `npm run build`。
- 最后汇报修改文件、是否改业务逻辑、`build` 是否通过。
- 如果只是更新文档，应明确说明没有修改代码；是否运行 build 以当轮任务要求为准。

## 六、本轮参考文件中最有用的 UI 规则摘录

- Ventriloc 的核心价值不在橙色品牌色，而在“白卡片 + 暖灰画布 + 克制边框阴影 + 数据卡片作为 hero visual”的结构。
- 其设计系统强调 comfortable density：内容不空，但每个模块之间要有明确呼吸。
- 导航胶囊、pill 按钮、8px 卡片圆角、20px 控件圆角，是可迁移的组件语言。
- 视觉层级主要通过背景对比、边框、留白和轻阴影完成，而不是靠重阴影或大色块。
- dashboard preview 应该像产品能力的浓缩演示：检索、指标、图表、释读卡片都应可一眼理解。
- 首页不是后台管理页；它要像系统的“第一段介绍”，负责总领全局。
