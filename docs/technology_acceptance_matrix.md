# 技术—接口—页面验收矩阵

版本：`2.0`

基线日期：`2026-06-19`

契约基线：`2026-06-19-converged`

## 1. 验收口径

面向用户的能力只有同时满足以下条件才算“已验收”：

1. 后端真实运行，不是固定返回或未调用骨架。
2. API 或可复现离线命令能够验证。
3. 正式前端页面真实消费，并保留加载、空结果和错误状态。
4. 后端测试通过；进入页面的能力还需要前端自动化或端到端测试。

“代码存在”“数据文件存在”“接口可返回”“运行时启用”和“正式前端
消费”是不同状态，不得合并描述。

## 2. 当前正式接口基线

正式接口以 `backend/main.py` 生成的 OpenAPI 为准，共 33 个操作，覆盖：

- 健康检查和 SQLite 看板。
- 关键词、高级、语义、混合检索及语义状态。
- RAG 上下文和风格上下文。
- Prompt 预览、释读生成、风格生成和一致性校验。
- 元数据统计、检索、详情和全文关联。
- 正文记录、金额、实体、地点、证据和检索单元。
- 图谱统计、记录子图、邻居、总览和地点流向。
- 在线文本规范化、实体、关系和生成任务槽位抽取。

已退出本版契约：

- `POST /api/generation/plain-interpretation`
- `GET /api/records/{record_id}/similar`

正式替代接口：

- 白话释读页面调用 `POST /api/generation/interpret`。
- 相似推荐暂无正式接口，等待真实向量相似实现后重新定义。

静默替代，也不得用于宣称后端能力已经完成。

## 5. 变更登记规则

每项正式能力变更必须同时检查：

1. `docs/api_contract.md`
2. `backend/tests/test_api_contract.py`
3. 对应后端集成测试
4. `frontend/src/api/` 与消费页面
5. 受影响的确定性 mock
6. 本矩阵和演示/测试文档

新增目录、类名、空表、占位函数或静态页面不能将状态改为“已验收”。

## 6. 目录所有权

- `frontend/`：正式产品前端，由 Frontend Developer 负责。
- `kg-viewer/`：图谱诊断沙盒，由 Frontend Developer 负责；不得作为正式
  页面验收替代。
- `docs/technology_acceptance_matrix.md`：由 Backend Developer 作为验收
  主责维护，跨层状态必须基于正式 API、正式页面和测试证据更新。
