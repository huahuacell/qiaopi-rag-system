## 1. 验收规则

一项面向用户或支撑用户功能的技术，只有同时满足以下四个条件，状态才能标记为“已验收”：

1. **后端真实运行（B）**：运行链路使用真实数据或真实算法，不是固定返回、占位函数或仅存在未调用的数据文件。
2. **API 可验证（A）**：技术结果通过稳定 API 返回，或对于纯离线技术，能够通过可重复的构建命令和构建报告验证。
3. **前端可使用（F）**：至少一个明确页面消费该结果，并保留加载、空结果和错误状态；纯离线技术必须能追溯到其下游页面。
4. **测试覆盖（T）**：至少包含后端自动化测试；进入页面的能力还必须补充前端组件或端到端测试。

状态定义：

- **已验收**：B/A/F/T 全部通过。
- **部分通过**：已有真实数据或部分链路，但至少一项验收门未通过。
- **未接入**：存在数据资产或代码骨架，但没有进入当前在线调用链。
- **占位**：当前实现是固定结果、空实现或明确的 placeholder。

任何字段重命名、删除、类型变化、必填性变化或语义变化，都必须同步更新：

- `docs/api_contract.md`
- `backend/tests/test_api_contract.py`
- 对应前端 API 封装和页面
- 前端 mock 数据
- 后端及前端测试

## 4. 当前验收结论

已经完成 B/A/F/T 四门闭环的基础能力：

1. FastAPI/OpenAPI/Pydantic/CORS 基础服务。
2. API 契约防漂移机制。

业务能力虽然已经真实接入，但因为前端尚无自动化测试，当前统一标记为“部分通过”：

1. 数据看板。
2. 关键词检索。
3. 记录详情。
4. 实体与证据展示。
5. 数据库摘要白话释读。
6. 确定性风格转换。

不能对外宣称已经完成的能力：

1. 向量语义检索。
2. BM25 与向量混合融合。
3. Qwen 生成。
4. 完整 RAG。
5. 在线 NLP 抽取。
6. 后端知识图谱查询与前端真实图谱。
7. 可复现的完整建库流水线。

## 5. 后续变更登记规则

每完成一项技术，提交时必须同时给出：

1. 后端实现文件和真实运行证据。
2. API 端点、请求样例和响应样例。
3. 前端页面路由和可见交互。
4. 后端测试名称及前端测试名称。
5. 本矩阵对应行从 `✗/△` 更新为 `✓` 的依据。

仅增加目录、类名、占位函数、数据库空表或前端静态图，不得将状态改为“已验收”。
