# Style Transfer RAG Explainability Script

## 一句话定位

这一页不是让大模型凭空模仿“古风”，而是先从侨批知识库检索与本次书信功能相匹配的真实表达，再把少量最佳样例注入 Prompt；生成后，系统继续把生成句反向映射到实际注入的知识库原文，并用独立规则检查人物、金额、地点和事件是否忠于用户输入。

## 演示时可直接使用的讲稿

“风格转换的核心不是单纯调用大模型，而是一条可追溯的 RAG 生成链路。系统首先分析本次输入需要哪些书信功能，例如称谓、问安、汇款、嘱托和结尾；同时识别收信关系。像‘淑兰：’这种没有直接写‘妻子’的输入，系统会结合姓名式称谓、共同子女、思念和归家语境，谨慎推断为夫妻关系。

确定槽位以后，每个槽位只在对应类型的侨批检索单元中召回候选。系统同时运行完整语境混合检索和槽位意图精确检索：前者采用关键词 BM25 与语义向量两路召回，在语义索引可用时通过 RRF 做排名融合；后者只保留与当前槽位相关的输入句和概念，防止长信中无关词语稀释“回信、保重、寄款”等核心意图。语义索引不可用时会明确降级为关键词检索，不会伪装成混合检索。两个候选池合并后再进行槽位重排，综合考虑原始排名、语义相似度、输入词句对齐、槽位纯度、文本质量、收信关系和关系表达形式。对称谓与落款而言，如果候选是‘慈亲大人膝下’，而本次关系被识别为夫妻，这个候选会受到强惩罚；“夫某泐、夫某顿、夫某字”等 `spouse_to_spouse` 真实落款则会获得额外加分。

每个启用槽位虽然保留多个候选供查看，但只有分数最高的一条会真正注入 Prompt，并且全部知识库上下文有九百字预算。这样既能让模型学到真实侨批的称谓、寄款句式和收束方式，又不会把大量原文堆进上下文造成拼贴或事实污染。当前使用的 Prompt 版本没有修改，变化发生在 Prompt 前面的检索与重排层。

生成完成后，页面的‘证据依据’不再重复展示显而易见的用户输入，而只展示知识库怎样参与了生成。系统先判断生成句承担的是称谓、问安、寄款、关怀、嘱托还是落款功能，再优先映射到同一功能槽位中实际注入的侨批片段；同时计算词句、字符二元组、事实结构和领域同义表达相似度。前端按知识单元合并重复命中，所以通常可以完整展示六类知识依据，但不会把同一原文重复铺满页面。页面会显示生成表达、知识库侨批原文、记录编号、检索方式、功能匹配分数以及‘已注入 Prompt’状态。

最后是一致性检查。它与 RAG 文体证据相互独立：知识库负责提供怎么写，用户输入仍是事实的唯一来源。系统会规范化中文金额，例如把三十元、二十元、十元分别解析为 30、20、10；会统一地点别名、亲属关系和寄递表达；再分别检查人物、金额、地点和生成边界。四张卡片各自读取对应检查项，一个寄款告警不会再把人物卡连带标红。只有确实发生人物关系改变、金额增删、地点替换或新增事实时，相关卡片才会进入复核状态。”

## 深层技术流程

1. **输入关系推断**
   - 优先使用明确亲属词。
   - 对无亲属词的姓名式称谓，结合共同子女、思念、归家等多类线索做保守推断。
   - 输出关系标签、置信度、推断理由和兼容的知识库 `relationship_type`。

2. **槽位激活**
   - `opening`、`closing` 是结构槽位。
   - `safety`、`remittance`、`family_care`、`instruction` 根据输入意图激活。

3. **混合召回**
   - 关键词通道负责精确命中历史词语与格式。
   - 语义通道负责召回意思相近但用词不同的表达。
   - 两路结果使用 RRF 融合，避免直接混用 BM25 和余弦分数的不同量纲。
   - 另设槽位精确分支，只检索相关输入句和功能概念；两组候选统一重排。

4. **槽位重排**
   - 原始排名：10%
   - 语义相似度：15%
   - 输入词句与概念对齐：25%
   - 槽位纯度：13%
   - 片段质量：12%
   - 收信关系兼容度：15%
   - 关系表达形式：10%
   - 对称谓、结尾中的关系冲突候选额外乘以 `0.35`。

5. **受控 Prompt 注入**
   - 每个启用槽位只注入最佳样例。
   - 注入总预算为 900 字符。
   - 金额、日期和署名等样例事实会被遮蔽或裁剪。
   - 当前启用上一版 `style-transfer-concise-json-v4` Prompt；v5 仍保留在版本库中，但不作为活动版本。

6. **生成后 RAG 溯源**
   - 只使用 `prompt_included=true` 的知识库片段进行归因。
   - 先识别生成句的书信功能，再对同槽位证据做词元、字符二元组、事实结构和领域同义归一化匹配。
   - 单句最多保留三个功能依据；前端按知识单元合并重复命中。
   - 未注入的候选不会被页面声称为生成依据。

7. **独立事实一致性检查**
   - 人物关系、金额、地点、日期、姓名、寄递和嘱托分别检查。
   - 中文复合金额按数值解析，避免把“三十元”误识别成“十元”。
   - “带回、捎回、寄回、妥收”等侨批语境表达被纳入寄递检查。
   - 前端按检查名称单独着色，不使用“一处失败全部标红”的联动逻辑。

## 与普通网页版 AI 的区别

- 普通 AI 通常只能给出生成结果；本系统可以给出实际检索到的 `record_id`、`unit_id` 和侨批原文。
- 页面区分“检索候选”和“已注入 Prompt”，不把没有进入模型上下文的材料冒充生成依据。
- 页面展示关键词、语义或混合检索的真实运行状态，语义不可用时明确降级。
- 文体依据与事实检查分层：知识库证明写法来源，一致性规则证明内容没有漂移。
- 结果可被复验：同一输入、同一索引版本、同一 Prompt 版本和同一检索配置可以重建检索与校验过程。
